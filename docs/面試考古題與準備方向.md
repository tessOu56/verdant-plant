## A. React × WebSocket

### A1. 為什麼在 React 用 WebSocket 常出錯？請把重連邏輯寫成一個 hook。

這是最高頻的題。面試官想確認你知道**連線是副作用、不該放在 render**，而且知道重連/心跳/清理要怎麼收在一個 hook 裡。答題要點：連線放在 `useEffect` 並回傳 cleanup 關閉；重連用**指數退避加抖動**；用 **ref 存 socket** 避免每次 render 重建；訊息用 callback ref 避免 stale closure。

可背的骨架：

```ts
import { useEffect, useRef, useState, useCallback } from 'react';

type Status = 'connecting' | 'open' | 'closed';

export function useSocket(url: string, onMessage: (data: any) => void) {
  const [status, setStatus] = useState<Status>('connecting');
  const sockRef = useRef<WebSocket | null>(null);
  const retriesRef = useRef(0);
  const lastMsgRef = useRef(Date.now());
  const onMsgRef = useRef(onMessage);
  onMsgRef.current = onMessage;               // 永遠拿到最新 callback，避免 stale closure

  const connect = useCallback(() => {
    const ws = new WebSocket(url);
    sockRef.current = ws;
    setStatus('connecting');

    ws.onopen = () => { retriesRef.current = 0; setStatus('open'); };
    ws.onmessage = (e) => { lastMsgRef.current = Date.now(); onMsgRef.current(JSON.parse(e.data)); };
    ws.onclose = () => {
      setStatus('closed');
      const delay = Math.min(1000 * 2 ** retriesRef.current, 15000) + Math.random() * 400; // 退避 + 抖動
      retriesRef.current++;
      setTimeout(connect, delay);
    };
    ws.onerror = () => ws.close();            // 統一走 onclose 的重連路徑
  }, [url]);

  useEffect(() => {
    connect();
    const hb = setInterval(() => {            // 心跳偵測：超過 20s 沒收到訊息就主動斷線重連
      if (Date.now() - lastMsgRef.current > 20000) sockRef.current?.close();
    }, 5000);
    return () => { clearInterval(hb); sockRef.current?.close(); }; // cleanup 一定要有
  }, [connect]);

  const send = useCallback((data: any) => {
    if (sockRef.current?.readyState === WebSocket.OPEN) sockRef.current.send(JSON.stringify(data));
  }, []);

  return { status, send };
}
```

追問常見延伸：為什麼不直接用 state 存 socket？（會觸發 re-render 且拿不到即時值，用 ref。）React 18 StrictMode 開發模式 effect 會跑兩次導致連兩條連線怎麼辦？（cleanup 要確實關閉，或用旗標忽略第一次；上線 build 不會雙跑。）

### A2. WebSocket 心跳為什麼需要？ping/pong 誰發？

長連線可能「假死」——TCP 沒斷但實際收不到資料，`onclose` 不會觸發。所以要應用層心跳：一種是前端定時送 ping、伺服器回 pong，超時未回就重連；另一種是前端監看「最後一次收到任何訊息的時間」，超過閾值就主動 `close()` 觸發重連。瀏覽器的 WebSocket API 不讓你手動送 protocol 層的 ping frame，所以前端心跳通常是自訂的應用層訊息，或靠伺服器發 ping、瀏覽器自動回 pong。

### A3. 重連時 token 過期怎麼處理？

若 WebSocket URL 帶認證 token，**每次重連前要重新取得新 token**，否則過期 token 會讓重連以 401 失敗、白白浪費一次退避嘗試。答題時提這點會加分，代表你想過真實線上情境。

### A4. 樂觀更新（optimistic update）怎麼做？失敗如何回滾？

送出即時操作（例如共享花園裡「澆水讓植物長一階」）時，前端先假設成功、立即更新 UI，再等伺服器確認訊息校正；若伺服器回錯或逾時，就回滾到先前狀態。要點是**保留前一版狀態以便回滾**、給每筆操作一個 id 對帳，並處理「確認遲到」與亂序。任何延遲高又要即時感的協作場景都會問這題。

### A5. 高頻訊息如何不拖垮 React 渲染？

伺服器可能每秒推很多筆（狀態同步、即時協作、行情）。天真地每則訊息就 `setState` 會讓 React 每秒 re-render 幾十次。常見解法：用 **ref 累積、以 requestAnimationFrame 或固定間隔批次 flush 到 state**（把 N 則訊息合併成一次渲染）；把高頻資料和 UI 狀態分離；必要時用 `useSyncExternalStore` 或 Zustand 的 selector 訂閱只更新真正變動的元件。這題把 WebSocket 和效能兩條主軸接起來，答得好很加分。

## B. 網頁動效與效能優化

### B1. requestAnimationFrame vs setInterval 做動畫，差在哪？

`setInterval` 與螢幕刷新不同步，會掉幀或撕裂，分頁切到背景仍在跑（浪費電）；`requestAnimationFrame` 由瀏覽器在下一次重繪前呼叫，和刷新率同步（通常 60Hz≈16.6ms/幀），分頁在背景時自動暫停。動畫一律用 rAF。

### B2. 什麼是固定時間步長（fixed timestep）？為什麼需要？

如果每幀直接用「上一幀到現在的時間差」推進動畫，會在不同刷新率（60Hz vs 144Hz）或掉幀時產生不一致。做法是累積 deltaTime，用固定步長（例如 1000/60）在 while 迴圈裡更新邏輯、剩餘時間留到下一幀。骨架：

```js
const STEP = 1000 / 60;
let acc = 0, last = performance.now();
function frame(now) {
  acc += now - last; last = now;
  while (acc >= STEP) { update(STEP); acc -= STEP; }  // 邏輯固定步長
  render();                                           // 繪製每幀一次
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);
```

### B3. 長列表（數萬筆）為什麼卡？怎麼解？

卡在**DOM 節點太多**：佈局、繪製、記憶體都爆。解法是**虛擬列表 / 視窗化（windowing）**：只渲染可視範圍內的節點（加少量緩衝），用一個撐開總高度的 spacer 維持捲動條，捲動時依 scrollTop 換算要顯示哪一段。React 生態用 `react-window` / `@tanstack/react-virtual`。能講出「把 5 萬節點降到約 30 節點、FPS 從個位數回到 60」這種量化差距最好。

### B4. 前端記憶體洩漏有哪些常見來源？怎麼查？

常見來源：未 `clearInterval/clearTimeout` 的計時器、未 `removeEventListener` 的事件監聽、閉包長期持有大物件、被全域變數或快取持有的參照、detached DOM（DOM 已移除但 JS 仍持有）。在 React 特別常見的是 **`useEffect` 沒回傳 cleanup**、訂閱沒取消、WebSocket 沒關。排查用 Chrome DevTools › Memory 拍 heap snapshot 做前後對比、看 Detached elements，或用 Performance › Memory 看 heap 是否只升不降。

### B5. 弱網、低配裝置怎麼確保不卡？

裝置落差很大（新旗艦到低階手機）。答題方向：**降階策略**（低配時降幀率、關粒子/陰影、降解析度）；**資源加載**（雪碧圖/紋理圖集、預載關鍵資源、懶載非關鍵、壓縮與 CDN、避免一次載入巨圖）；**渲染成本控制**（減少 layout thrash、用 transform/opacity 觸發合成層而非改 top/left、離屏用 OffscreenCanvas）；弱網則要有重連、斷線續傳與 loading/skeleton。

### B6. 如何量測與定位效能瓶頸？

用 Chrome DevTools › Performance 錄一段互動，看**火焰圖**找出最耗時的函式（例如某次 update 或 layout），看是否有 Long Task、強制同步佈局（layout thrashing）、掉幀。線上則用 `PerformanceObserver` 收 FPS/長任務、用 web-vitals 收 LCP/INP。講得出「先量測再優化、不要憑感覺」是重要態度分。

### B7. DOM diffing / React 重渲染怎麼優化？

要點：避免不必要 re-render（`React.memo`、`useMemo`/`useCallback` 穩定參照、state 盡量下沉到真正用到的元件）；穩定的 `key`（別用 index 當高頻變動列表的 key）；把高頻更新隔離成小元件；大量計算移到 worker。能連結到 A5（高頻 WebSocket 訊息批次化）會顯得體系完整。

## C. 前端 LeetCode / 即時互動實作題（現場手寫）

這類職缺技術關常要你**當場寫可跑的互動邏輯**，不是純演算法。準備方向是把下列「元件級」題目練到能 20 分鐘內寫完並講清楚：

- 防抖 debounce / 節流 throttle（並解釋動畫用 throttle、搜尋用 debounce）。
- 手寫一個可重連的 WebSocket 包裝（就是 A1 的骨架，去掉 React 也要會純 JS 版）。
- 倒數計時器 / 碼表（處理 setInterval 漂移，用 `Date.now()` 校正而非累加）。
- 實作簡易 Promise、`Promise.all`、並發限制（concurrency pool）——即時系統常考。
- 事件發射器 EventEmitter（on/off/emit），延伸到記憶體洩漏（off 沒呼叫）。
- 虛擬列表的核心換算（scrollTop → 顯示區間）。
- 用 rAF 寫一個平滑動畫（數字滾動、進度條、緩動）。

答題習慣：先問清楚需求與邊界、講思路再寫、寫完主動講複雜度與如何測試/如何處理錯誤與清理。即時互動類特別在意**清理（cleanup）與邊界情境**，主動提就是加分。
